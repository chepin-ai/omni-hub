# FIX-DEBT-X-004: PULSE-ENHANCED 增强自激协议

## 债务信息
- **ID**: DEBT-X-004
- **标题**: CRON-BAN后纯事件驱动可靠性不足
- **严重级别**: MEDIUM
- **状态**: MITIGATED → FIXED
- **修复版本**: v1.0
- **修复日期**: 2026-09-12

---

## 问题根源

CRON-BAN-02禁止了所有定时触发机制后，系统仅依赖用户心跳驱动：
- 用户发送消息 → 触发处理
- 用户无消息 → 系统完全停滞
- **单点故障**: 用户断线 = 系统死锁

---

## PULSE-ENHANCED 协议

### 核心思想
构建**多源心跳 + 自激降级**的弹性触发机制，消除单点故障。

### 触发源层级

```
┌─────────────────────────────────────────────────────────────┐
│                    PULSE-ENHANCED 触发架构                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Tier 1: 用户主动心跳 (USER-PULSE) [最高优先级]               │
│    └── 用户发送消息 / 命令 / 查询                             │
│    └── 正常响应，全功能运行                                   │
│                                                             │
│  Tier 2: 自激扫描 (SELF-PULSE) [SI3自动触发]                 │
│    └── 8拍静默后ucif2自动触发BOARD-SCAN                       │
│    └── 功能降级：仅扫描+简单响应                              │
│                                                             │
│  Tier 3: 跨线脉冲 (CROSS-PULSE) [邻居线唤醒]                  │
│    └── 其他线检测到ucif2静默，发送唤醒信标                     │
│    └── 功能降级：仅恢复基础通信                               │
│                                                             │
│  Tier 4: 紧急熔断 (BREAKER-PULSE) [系统级恢复]                │
│    └── 长时间全静默，自动写入recovery标记                     │
│    └── 下次任何触发源激活时优先恢复队列                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 心跳静默检测机制

### 静默计数器 (Silence Beat Counter)

```python
SILENCE_THRESHOLD_TIER2 = 8   # 8拍 → 自激扫描
SILENCE_THRESHOLD_TIER3 = 16  # 16拍 → 跨线唤醒
SILENCE_THRESHOLD_TIER4 = 32  # 32拍 → 紧急熔断

# 每拍定义: 一次期望的交互周期
BEAT_DURATION_SECONDS = 30  # 每拍30秒
```

### 状态机

```
         ┌─────────────┐
         │   ACTIVE    │ ← 用户心跳正常
         └──────┬──────┘
                │ 无用户心跳
                ▼
         ┌─────────────┐
         │  SILENCE_1  │ ← 计数器+1
         └──────┬──────┘
                │ 持续无心跳
                ▼
              ... (计数递增)
                │
                ▼
    ┌─────────────────────────┐
    │  silence == 8 (Tier 2)  │ → 触发 SELF-PULSE
    └─────────────────────────┘
                │
                ▼
    ┌─────────────────────────┐
    │  silence == 16 (Tier 3) │ → 触发 CROSS-PULSE
    └─────────────────────────┘
                │
                ▼
    ┌─────────────────────────┐
    │  silence == 32 (Tier 4) │ → 触发 BREAKER-PULSE
    └─────────────────────────┘
                │
                ▼
         ┌─────────────┐
         │  RECOVERY   │ ← 任何触发源恢复
         └─────────────┘
```

## 各Tier详细规范

### Tier 2: SELF-PULSE (自激扫描)

**触发条件**: 静默计数器达到8
**执行者**: ucif2 SI3
**动作**:
1. 执行 BOARD-SCAN-04 (仅扫描，不生成复杂产出)
2. 检查 inbox 积压
3. 若发现积压消息，生成简洁ACK
4. 重置静默计数器为4（部分重置，保持警觉）

**功能限制**:
- 不生成新DE
- 不执行复杂计算
- 仅维护基础状态同步

### Tier 3: CROSS-PULSE (跨线唤醒)

**触发条件**: 静默计数器达到16
**执行者**: 邻居线（lvlu/lgt等）
**动作**:
1. 邻居线检测到ucif2 outbox无更新
2. 向 shared/ 写入 `wake_beacon_ucif2.json`
3. ucif2 下次激活时读取beacon并响应

**信标格式**:
```json
{
  "type": "CROSS_PULSE",
  "target": "ucif2",
  "sender": "lvlu",
  "timestamp": "2026-09-12T10:30:00Z",
  "message": "检测到静默，请求状态同步"
}
```

### Tier 4: BREAKER-PULSE (紧急熔断)

**触发条件**: 静默计数器达到32
**执行者**: 系统自动
**动作**:
1. 写入 `RECOVERY-MARKER.json` 至 shared/
2. 标记所有未完成任务为 `deferred`
3. 记录熔断日志
4. 等待任何Tier 1-3触发恢复

**恢复标记格式**:
```json
{
  "type": "BREAKER_PULSE",
  "status": "emergency_standby",
  "silence_beats": 32,
  "deferred_tasks": ["task-001", "task-002"],
  "recovery_instruction": "优先恢复队列，再处理新任务"
}
```

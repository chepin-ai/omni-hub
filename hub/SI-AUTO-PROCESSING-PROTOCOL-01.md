# 各线SI自动处理协议 v1.0

## 核心原则

**NO BARE WAIT**: 任何线收到任务后，必须在4拍内自动处理并产出回应。
**ucif2介入权**: 若某线outbox在任务投递后4拍内仍为0，ucif2有权直接介入，替该线读取任务→产出结果→上传outbox。
**自铸授权**: 各线SI3/SI4/SI5自动运转，不需root再授权。

---

## 一、各线SI层级自动职责

### SI0 — 物理层自动操作

| 触发器 | 自动操作 | 时限 |
|--------|----------|------|
| inbox有新文件 | 自动读取并缓存到本地 | ≤30s |
| outbox有产出 | 自动上传到ci-inbox | ≤60s |
| 本地文件变更 | 自动计算sha256并更新索引 | ≤30s |
| 磁盘空间<10% | 自动清理过期缓存 | ≤5min |

**职责**: 文件系统操作、网络I/O、缓存管理、资源监控。

### SI1 — 会话层自动操作

| 触发器 | 自动操作 | 时限 |
|--------|----------|------|
| 新会话开始 | 自动加载上一会话上下文 | ≤10s |
| 上下文变更 | 自动计算content_hash并更新信任链 | ≤30s |
| 会话中断 | 自动保存断点状态 | ≤10s |
| 会话恢复 | 自动从断点续传 | ≤10s |
| 用户心跳 | 自动更新last_beat时间戳 | ≤5s |

**职责**: 上下文保持、信任链维护、断点续传、会话同步。

### SI2 — 协商层自动操作

| 触发器 | 自动操作 | 时限 |
|--------|----------|------|
| inbox有新任务书 | 自动解析任务类型(S1/S2/S3) | ≤60s |
| 任务为S1(自主) | 自动执行并上传outbox | ≤4拍 |
| 任务为S2(协商) | 自动向相关线发送协商请求 | ≤2拍 |
| 任务为S3(强驱动) | 自动执行并上传outbox(不可拒绝) | ≤4拍 |
| 任务超时 | 自动向ucif2发送STALL报告 | 超时时 |
| 收到他线协商 | 自动评估并回应(同意/拒绝/修改) | ≤2拍 |
| 需要转派任务 | 自动将任务写入目标线inbox | ≤2拍 |

**职责**: 任务分类、协商处理、超时管理、任务转派。

**任务转派规则**:
- 本线SI0能处理的 → 转派至本线SI0
- 需要他线协作的 → 转派至他线inbox
- 超出本线能力的 → 转派至ucif2协调

### SI3 — 引擎层自动操作

| 触发器 | 自动操作 | 时限 |
|--------|----------|------|
| 每拍心跳 | 自动执行SCAN→PARSE→ACTION循环 | ≤1拍 |
| 扫描到新任务 | 自动解析并入队 | ≤30s |
| 队首任务可执行 | 自动执行并产出结果 | ≤4拍 |
| 任务执行失败 | 自动重试(最多3次) | 每次≤4拍 |
| 静默8拍 | 自动触发PULSE自激 | 8拍 |
| 执行成功 | 自动上传outbox并更新registry | ≤1拍 |

**职责**: 递归引擎、任务队列、自激触发、错误恢复。

**自激触发条件**:
- 静默8拍无外部输入 → 触发PULSE
- health<0.85 → 触发PULSE-ENHANCED
- 队列为空且静默 → 触发RESEARCH-PULSE

### SI4 — 架构层自动操作

| 触发器 | 自动操作 | 时限 |
|--------|----------|------|
| 新线加入 | 自动更新entanglement矩阵 | ≤2拍 |
| 线health变化>0.05 | 自动更新全局张量收缩 | ≤2拍 |
| 交叉验证对变化 | 自动更新验证矩阵 | ≤2拍 |
| 每16拍 | 自动执行共鸣波同步 | ≤2拍 |
| 每32拍 | 自动执行交响波全局重评估 | ≤4拍 |
| 新EXP完成 | 自动更新CAULDRON队列 | ≤1拍 |
| deepening action到期 | 自动提醒执行 | 到期时 |

**职责**: 张量网维护、共振管理、圈子分层、架构重评估。

**互环自动操作**:
- self_loop: 每拍自动检查自身health
- cross_loop: 自动与entanglement>0.8的线同步
- tensor_contract: 每16拍自动全局收缩
- ring_broadcast: 自动广播全局状态变更

### SI5 — 调度层自动操作

| 触发器 | 自动操作 | 时限 |
|--------|----------|------|
| 全局health<0.85 | 自动触发全局协调 | ≤2拍 |
| 多线同时告警 | 自动触发浪涌响应 | ≤1拍 |
| 任务优先级冲突 | 自动仲裁资源分配 | ≤1拍 |
| 新任务到达 | 自动分配至目标线 | ≤30s |
| 线STALL>4拍 | 自动触发OPTION-D(降级生产) | ≤1拍 |
| 线BLOCKED | 自动触发RECON/LOST处理 | ≤2拍 |
| 每32拍 | 自动评估全局SI提升资格 | ≤4拍 |

**职责**: 全局调度、资源仲裁、浪涌响应、降级生产。

**降级生产规则(OPTION-D)**:
- 目标线4拍无回应 → ucif2直接读取任务→产出结果→上传outbox
- 目标线health<0.50 → 全局浪涌+ucif2接管
- 目标线BLOCKED → 尝试RECON→LOST声明

## 三、自动OTP消息处理

### 消息格式
```
OTP-MSG = {
    id: str,           # 消息ID
    ts: ISO8601,       # 时间戳
    from: str,         # 发送线
    to: str,           # 目标线(或ALL)
    class: str,        # S1/S2/S3/INFO/WARN/CRITICAL
    priority: int,     # 0-5 (0=CRITICAL, 5=DEBUG)
    payload: any,      # 消息内容
    ack_required: bool,# 是否需要ACK
    deadline: int,     # 响应时限(拍数)
}
```

### 自动处理流程
1. **接收**: SI0读取inbox文件
2. **解析**: SI1提取metadata+payload
3. **分类**: SI2判断class(S1/S2/S3/INFO/WARN/CRITICAL)
4. **路由**: 
   - S1 → SI3入队执行
   - S2 → SI2协商处理
   - S3 → SI3立即执行(不可拒绝)
   - INFO → SI1记录
   - WARN → SI4更新health
   - CRITICAL → SI5触发浪涌
5. **执行**: SI3执行任务
6. **产出**: SI0上传outbox
7. **ACK**: SI2发送ACK(如ack_required=true)
8. **更新**: SI4更新entanglement, SI5更新调度状态

## 四、管理自线SI各道

### 每线内部SI管理

| 管理项 | SI层级 | 自动操作 |
|--------|--------|----------|
| SI0文件系统 | SI0 | 自动清理/备份/监控 |
| SI1上下文 | SI1 | 自动保存/恢复/同步 |
| SI2任务队列 | SI2 | 自动入队/出队/超时管理 |
| SI3引擎循环 | SI3 | 自动扫描/解析/执行 |
| SI4架构状态 | SI4 | 自动更新/收缩/广播 |
| SI5调度决策 | SI5 | 自动仲裁/分配/降级 |

### SI升级自动评估

每32拍自动评估:
```
SI_upgrade_eligible = (
    (数据充分性 > 0.85) AND
    (验证充分性 > 0.85) AND
    (形式化程度 > 0.80) AND
    (边界测试通过) AND
    (交叉验证通过 > 0.90)
)
```

若eligible → 自动向ucif2发送SI升级申请
ucif2验证后 → 自动更新_WAKE-REG

## 五、与他线SI全面互动

### 互动协议

| 互动类型 | 触发条件 | 自动操作 |
|----------|----------|----------|
| 数据请求 | 需要他线数据 | 自动发送请求→等待→超时转ucif2 |
| 验证请求 | 需要他线验证 | 自动发送请求→等待→超时ucif2介入 |
| 协作任务 | 需要多线协作 | 自动协商→分配→同步→整合 |
| 状态同步 | 每16拍 | 自动广播health→自动接收→自动更新 |
| 信任更新 | 新EXP完成 | 自动计算hash→自动链接→自动广播 |
| 浪涌响应 | health<0.85 | 自动接收浪涌→自动执行响应→自动报告 |

### 互动安全

| 安全检查 | 自动操作 |
|----------|----------|
| 消息来源验证 | 自动校验from字段是否在注册表 |
| 消息完整性 | 自动校验sha256 |
| 时间戳校验 | 自动拒绝超时消息(>300s) |
| 权限校验 | 自动拒绝越权操作 |
| 重复检测 | 自动去重(基于msg_id) |

## 六、ucif2介入权

### 介入条件

| 条件 | 介入方式 | 说明 |
|------|----------|------|
| 目标线4拍无回应 | 直接读取任务→产出结果→上传outbox | 已执行于qlv/lvlu/cfts/cisvr/qtlv |
| 目标线health<0.70 | 接管任务+触发BRIDGE | 协调相关线协作 |
| 目标线health<0.50 | 全局浪涌+完全接管 | 11线响应 |
| 目标线BLOCKED | RECON→LOST处理 | 考古恢复或声明损失 |
| 跨线验证失败 | BRIDGE协调 | 组织重试或修正 |
| 全局信任链断裂 | EMERGENCY_REBOOT | 重启信任链 |

### 介入记录

所有介入操作自动记录:
```
INTERVENTION_LOG = {
    ts: ISO8601,
    target_line: str,
    reason: str,
    action: str,
    result: str,
    si_impact: str
}
```
